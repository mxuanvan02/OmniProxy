# Changelog

All notable changes to OmniProxy are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed
- **The one-click update no longer fails with `exec: "bash": executable file not found in $PATH`.** The launchd job runs with `PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/usr/sbin:/sbin` — no `/bin`, which is where macOS keeps `bash`, `date` and `launchctl`. Go resolves `exec.Command("bash", …)` through the PARENT process's PATH, and `cmd.Env` does not influence that lookup, so the spawn died before the script ever ran and the endpoint answered `500` having swapped nothing. The shell is now resolved explicitly (the operator's PATH first, then the POSIX system directories) and invoked by absolute path, and the child's `PATH` gets the missing system directories appended so `update.sh` can reach `date` and `launchctl` too. Caught by a real end-to-end run — the stubbed tests had stayed green because `go test` inherits an ordinary shell PATH — and the regression test reproduces it by running with the launchd PATH shape minus `/bin`.

## [0.6.2] — 2026-10-05

### Fixed
- **The dashboard's one-click update compares against the running binary, not `version.json`.** In repo layout `version.json` is git-tracked, so a `chore(release)` commit bumps it to the new tag while the service is still running the binary it started as — `config.Version` is read once at startup and never re-read. `update.sh` keyed "already installed" off that file, so it concluded `already at 0.6.1`, exited 0, and the dashboard reported a successful update having swapped nothing: the operator saw "new version available" → "update complete" → reload → still the old version, forever. Invisible on a tarball install, where only the script writes the file; fatal on the layout the dashboard actually runs from a clone. The endpoint now passes the version of the process serving the request (`OMNIPROXY_INSTALLED_VERSION`, taken from `config.Version` — not from the request, so the no-injection property is unchanged) and `update.sh` prefers it over the file, falling back to it only when unset. Both sides carry a regression test, each verified by mutation: neutering the env pass fails the Go test with `SEEN=<unset>`, neutering the shell preference fails sandbox T11. T11 also covers the converse — a process already at the latest is left alone even when the file lags — so the fix cannot cause needless swaps either.

## [0.6.1] — 2026-10-05

### Added
- **One-click update from the `/admin` dashboard.** The update modal previously only offered "Download" — it could see a new release and not install it. It now has an "Update now" button that runs the updater in place: a progress view streams the script's own output and the proxy comes back on the new version without an SSH session. The endpoint pair takes **no input from the request** — the script path is resolved from the working directory or beside the executable, never from a client-supplied value, so there is no path to inject. A second click or a second tab gets `409 Conflict` instead of racing the swap.
  **All update state lives on disk** (`data/update.state`, `data/update.log`), not in memory, because the updater restarts the very process that spawned it: an in-memory log would die at exactly the moment the operator most needs it. The script is spawned detached into its own process group (a `launchctl kickstart -k` restart would otherwise take the updater down mid-swap), it records its own exit code in a fixed wrapper — passing paths as `$1`/`$2` rather than interpolating them into the shell text — and the freshly restarted proxy reads the same two files and reports honestly. A `running` flag older than 15 minutes is treated as stale rather than locking updates out forever, and the log is capped at 256 KiB on read so a runaway script cannot balloon an admin response. The UI polls status rather than holding a stream open: a failed poll is the restart happening, not an error, and only ~60s of silence is reported as a failure.
- **Release tarballs ship `scripts/`.** The one-click update runs `scripts/update.sh` beside the binary; a tarball install without it could detect a new version but not install one. The workflow now packages `scripts/` next to `web/`.

### Changed
- **`scripts/update.sh` gains a `repo` layout.** It assumed `~/.omniproxy-user/bin/{omniproxy,web}` + systemd, so on an install where the binary sits directly in a git checkout it would have written `bin/omniproxy`, left launchd running the old binary, and reported success — a silent failure, the worst kind. `--layout repo` (or `OMNIPROXY_LAYOUT=repo`) puts the binary and `web/` in the repo directory and restarts via `launchctl kickstart -k`, which kills and restarts the job so the swapped binary is what comes up (a plain `launchctl start` is a no-op on an already-running job). The `prefix` layout keeps its old behavior and remains the default. The optional `scripts/` install is now `prefix`-only, so a repo layout never overwrites its own git-tracked updater.
- **The Usage page names API keys instead of printing their IDs.** Recent Requests showed a bare 8-character ID prefix and the "Usage by API Key" aggregate showed a raw UUID — unreadable when several keys are in play. Both now resolve the ID to the key's human name through a new `apiKeyNames` map the backend builds in `GetStats` from config, the same way `accountNames` already works: one source of truth, sent down with the stats rather than fetched a second time by the frontend, so renaming a key in Settings retro-applies to every historical row without rewriting records. An unnamed key falls back to its masked value (what the API Keys settings page shows, so both surfaces agree), a key since deleted falls back to a short ID prefix, and the full ID stays in the cell's `title` for tracing. The raw key value is never a label.

### Fixed
- **A Claude session is no longer silently downgraded to a cheaper model on a transient error.** When `fallbackModel` was unset, `Apply` seeded it with a sonnet model, so one upstream hiccup on an opus session moved the rest of that session onto sonnet. The fallback is now seeded from the session's primary model — the operator's intent is retry-in-place, not downgrade — and with no primary configured nothing is seeded, rather than inventing a model. An explicitly chosen `fallbackModel` is still never retargeted.
- **Coalesced config saves can no longer write into a directory that is being torn down.** `scheduleSave`'s process-global loop sleeps between scheduling and writing against the *current* `cfgPath`; a save scheduled near the end of one test woke after the next test's `Init(t.TempDir())` had repointed the singleton and wrote a `.config.json.tmp-*` sibling into a directory mid-cleanup — the source of the intermittent `TempDir RemoveAll cleanup: directory not empty` CI failure under `-race`. `Init` now drains the queued token and clears `pendingSave` before repointing, flushing outstanding counters to the old path first so a legitimate re-`Init` does not drop them, and the sleeper's flush is a no-op when it wakes.
- **The Recent Requests table no longer scrolls sideways.** Recent Requests showed a bare 8-character ID prefix and the "Usage by API Key" aggregate showed a raw UUID — unreadable when several keys are in play. Both now resolve the ID to the key's human name through a new `apiKeyNames` map the backend builds in `GetStats` from config, the same way `accountNames` already works: one source of truth, sent down with the stats rather than fetched a second time by the frontend, so renaming a key in Settings retro-applies to every historical row without rewriting records. An unnamed key falls back to its masked value (what the API Keys settings page shows, so both surfaces agree), a key since deleted falls back to a short ID prefix, and the full ID stays in the cell's `title` for tracing. The raw key value is never a label.

### Fixed
- **The Recent Requests table no longer scrolls sideways.** The table carried `min-width: 720px` and its wrapper only set `overflow-y: auto` — which makes the browser compute `overflow-x: auto` too — so on any card narrower than 720px the operator had to drag the table left and right to read the last columns. The table is now pinned inside its card at every width: `table-layout: fixed` with explicit per-column widths, `overflow-x: hidden` on the wrapper, and every cell ellipsizing with its full value in `title`. Measured in a real browser at 375/640/900/1280/1600px card widths: `scrollWidth == clientWidth` at all five, so there is no horizontal overflow to scroll. The inline error message under the timestamp keeps real wrapping (`white-space: normal`) since the cell-level `nowrap` would have collapsed its two-line clamp to one clipped line.

## [0.6.0] — 2026-10-04

### Added
- **Per-request cost and latency provenance in Usage.** Every usage record now carries the upstream HTTP status for the attempt, dispatch-to-record latency, and the cost source that produced the credit figure — `provider` (the gateway's own published price list) or `vendor` (the built-in list price, i.e. an estimate for resellers whose real rate is unknown). Failure statuses are recovered from the adapter error strings (`HTTP %d from …`, anchored on the literal prefix so Ray IDs and Cloudflare HTML digits are not misread); zero honestly means "no HTTP response ever arrived" (connection reset, timeout, cut stream) and the UI renders an em dash instead of inventing a code. A 200 with `status: error` is a real shape: the stream opened, then was cut.
- **Plan-window credit ceilings from the gateway itself.** For new-api style gateways the subscription window is now sized in credits: `/api/subscription/plans` supplies each plan's `total_amount` (quota units), the public `/api/status` supplies `quota_per_unit` (quota per 1 USD), and credit = quota / quota_per_unit × 100 — 1 credit = 1 US cent on VSLLM, pinned two independent ways (the marketplace lists a request at "0.2 credit" that bills $0.002; the top-up page labels a 500000-quota plan "100 credit"). A 78%-used 1000-credit plan reads "780 / 1000" instead of a bare percentage bar. Both rates are read from the API rather than hardcoded, because `quota_per_unit` is a per-gateway operator setting. A plan the catalog does not list leaves the ceiling unknown and falls back to the percentage bar rather than printing a fabricated total.
- **Kind and Credit columns per request in the Usage table.** Recent Requests now shows which endpoint type served each request (chat, responses, image, video, search — derived from the record's endpoint + dialect), split Input/Output/Cache token columns, the request's cost in the gateway's display credit beside USD, the upstream status code and latency. Locale keys added in EN/VI/ZH; the credit and status columns carry tooltips explaining the unit (1 credit = $0.01) and what an em dash means.

### Changed
- **Usage page layout: Recent Requests gets the full width.** The topology map (hub-and-spoke account graph) is removed from the page so the request table is no longer squeezed into a third of the screen; the table is now the page. `renderTopology()` and its CSS rules remain in-tree, unused, pending the permanent remove-or-restore decision.
- **Capability tags reconcile with probe evidence.** Discovered capability tags were derived purely from model-name heuristics: an account advertising `gemini-embedding-001` got an "embedding" tag even though the probe recorded a 403, and a verified 200 vision probe stayed invisible. Tags now consult the stored probe record: a passing probe adds the capability, a failing probe with a definitive 4xx drops it, and an inconclusive result (timeout, no HTTP status, skipped) leaves the tag unchanged so one slow gateway cannot delete evidence. The raw unreconciled set still governs probe eligibility, so a dropped tag keeps being re-probed and recovers on its own when the gateway starts working again; a timeout can no longer overwrite a previously verified verdict.

### Fixed
- **Blank-SSE resale gateways no longer kill every streamed turn.** Some resale gateways advertise a model, accept the request, then answer a streamed call with an SSE body carrying only metadata (role, finish_reason, usage) and no text, while the same body without `stream` returns the completion normally. Measured on a live reseller for `claude-opus-4-8`: every pool retry hit the blank stream and the turn died with "ended without assistant output". An account can now opt out of upstream streaming (`ExternalUpstreamStream: false`); the outbound request sends `stream: false` with a JSON `Accept` and no `stream_options`, and the handler still replays the buffered completion to the client as SSE. Streaming stays the default: only an explicit `false` opts out, and the pointer distinguishes "unset" from "false" so one account's opt-out can never silently change another's.

## [0.5.1] — 2026-10-02

### Added
- **Release binaries + fast self-update.** A `v*` tag now triggers `.github/workflows/release.yml`: prebuilt binaries for linux/darwin (amd64+arm64) and windows (amd64), each packaged with `web/` plus a `version.json` stamped from the tag, sha256-verified, published as a GitHub Release whose notes are the matching CHANGELOG section. `scripts/update.sh` applies a release to a running install — `--check` is read-only; the update path verifies the sha256 before touching anything, backs the current binary up under `.rollback/` (5 kept, pruned by filename so a fresh backup is never the one deleted), swaps the binary with an atomic rename and `web/` with a single rename while keeping the previous copy aside, restarts via systemd-user (or `OMNIPROXY_RESTART_CMD`), health-checks `/v1/models` for 30s, and writes `version.json` only once the new version is healthy. A failed restart or health check restores binary **and** web, restarts again and exits non-zero — with `version.json` still on the old version, so re-running retries instead of reporting "already up to date". Sandbox-tested: `scripts/test-update-sandbox.sh` runs the script against a fake release API on ephemeral ports and covers check / update / rollback / retry-after-rollback / up-to-date / tampered-tarball / fresh-install-with-empty-rollback / restart-failure / prune-safety.
- README (EN/VI/CN): "Update to a new release" section under Installation; the OpenAI-compatible-gateway bullet now lists the 0.5.0 additions (per-account Responses dialect, plan-window quota bars, verbatim parameter passthrough).

## [0.5.0] — 2026-10-01

### Security
- **Admin auth is now a session token.** `POST /admin/api/login` exchanges the password for a 12-hour token compared with `crypto/subtle.ConstantTimeCompare`; every other admin route requires it in `X-Admin-Token`. The `?pwd=` query parameter and the `admin_password` cookie are gone — a password could previously leak through referrers, proxy access logs and browser history. The two SSE routes (`/admin/api/logs/stream`, `/admin/api/usage/stream`) accept `?token=` because `EventSource` cannot set headers. The dashboard no longer stores the password anywhere; legacy `admin_password` / `kiro_remembered_pwd` storage keys are purged on load.
- **CORS no longer wildcards the admin API.** `/admin/api/*` echoes `Access-Control-Allow-Origin` only for same-origin or loopback requests; `/v1/*` keeps `*` for API clients. The admin API returns every stored upstream OAuth token, so any page the operator visited could previously read them cross-origin.
- **Default bind is `127.0.0.1`.** A fresh install is no longer reachable from the LAN. Existing configs keep their stored `host`; containers opt back in via `docker-compose.yml`.
- **`changeme` and blank admin passwords are refused.** A 24-byte random password is generated on first run and printed once to stderr (never through `logger`, whose ring buffer is replayed by `/admin/api/logs`). `ADMIN_PASSWORD` is held to the same floor, and the check trims first, so `" "` is rejected as blank rather than stored as a one-space secret.
- **Changing the admin password revokes every existing session.** An operator rotating a password they believe compromised previously left the attacker's token valid for its full 12-hour life; only the browser that made the change re-authenticated.
- Client API keys and the legacy key are compared with `crypto/subtle` over SHA-256 digests, so neither the value nor its length leaks through timing.
- Credential files written by the CLI-tool integrations (VS Code secrets, `~/.codex/auth.json`, Kilo, DeepSeek/JCode, 9router, Hermes, Droid, OpenClaw) and config backups are `0600`, their directories `0700` — previously `0644`/`0755`.
- SSRF guard on the one client-supplied URL (`jina-reader`): scheme must be http/https, and loopback / RFC1918 / CGNAT / link-local targets are rejected after DNS resolution, so cloud metadata endpoints are unreachable.
- `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and `X-Frame-Options: DENY` on the admin pages; static assets are served by `http.FileServer`, which cannot be walked out of its root.
- Request bodies on the inference paths are capped at 64 MiB and answered with 413 instead of being buffered unbounded.

### Fixed
- **A stalled upstream parked the account, then aborted every later request instantly.** Two transport shapes that say nothing about the credential matched no marker in `isTransientNetworkError`, so `handleAccountFailure` reached its default branch and charged a cooldown for each: the transport's own response-header deadline (`http2: timeout awaiting response headers`), and `EADDRNOTAVAIL` read from a pooled connection the local stack had already torn down (`read: can't assign requested address`, seen on macOS in the minute after the network drops, where two requests reuse the same dead socket in the same second). Three consecutive stalls then parked the account for a minute, and on a model only one provider serves, every request inside that minute found no candidate at all and failed immediately with `no account found after 0 attempts` — the account card stayed green throughout. Both shapes are now classified as transport faults, which is what the branch beside them already prescribes: rotate to the next account without recording a cooldown.
- **A newly added Antigravity account had no models until some later global refresh.** The add route stored the credential and reloaded the pool but never fetched the catalog, so the account card read `0 models`, the test modal said "Model list unavailable" and its Test button stayed disabled — the operator could not test the account they had just added, and could not see whether the Google verification step was still outstanding. The account's catalog is now fetched on add, as it already was on the generic add route.
- **`GET /admin/api/accounts/{id}/models` answered Antigravity accounts with a DNS error.** The handler branches for service, external, Codex and Gommo accounts but not for Antigravity, so the request fell through to Kiro's `ListAvailableModels` and sent the account's Google token to `q.external.amazonaws.com`. Both the dashboard's "Refresh models" action and the live model list were broken for every Antigravity account. The route now reads the catalog from `fetchAvailableModels` on the account's own endpoint.
- **A fallback Antigravity catalog was reported as provider-verified.** `fetchAntigravityModels` substitutes the static list on every failure path and returns a nil error, so the `fellBack` flag its callers derived from that error could never be set: the dashboard showed `catalogState: verified` for a list the provider had never confirmed. The function now reports the substitution explicitly, and the state is `static` when it applies.
- **The Antigravity verification link is now copyable.** The Google account behind an Antigravity proxy account is normally signed in on a different Chrome profile from the one running the dashboard, so clicking the "Verify account" button opened the verification page as the wrong user and the step never cleared. The account card and the failed-test log each carry a copy button beside the link, so the URL can be pasted into the profile that holds that account.
- **The verification link Google asks for was unreadable and unclickable.** An account stuck at `VALIDATION_REQUIRED` carries the page its owner has to open inside the 403 body — as `metadata.validation_url` on the `ErrorInfo` detail, repeated as a `google.rpc.Help` link — and that page is the only thing that clears the state. The admin UI never showed it: `truncateErrBody` caps the error text at 400 characters, which cuts the URL off mid-query, so even an operator who read the raw message got a dead link. The adapter now reads the link from the full response, persists it on the account as `antigravityVerifyUrl`, and clears it on the next successful call; the account card offers it as a "Verify account" button and the failed-test log renders it as a link rather than burying it in the message. The status badge drops the green "Normal" for "Needs verification" while the link is set, since the account reaches the upstream and is refused on every request — a healthy-looking card is how the state went unnoticed.
- **An Antigravity account was marked `BANNED` and switched off for a state the operator could clear in a browser.** When Google answered `403 PERMISSION_DENIED` / `VALIDATION_REQUIRED` ("Verify your account to continue"), the message was routed to the shared Kiro-shaped ban branches. `isAuthErrorMessage` matches any text carrying a standalone `403` — correct for Kiro, where a 403 means the account was rejected — and the guards beside it excluded external and Codex accounts but not Antigravity, so the account was recorded as terminated and disabled. "Test & Recover" could not clear it either: the test hit the same 403 and re-applied the ban, so the account was stuck showing Banned / Disabled with no path back. Antigravity now classifies `VALIDATION_REQUIRED` as its own recoverable state, logs the one action that clears it, and is excluded from the shared ban branches through a single `genericBanApplies` guard that all three sites now share; a genuinely terminated account (`"has been disabled"`, ToS enforcement) is still recorded as `BANNED`.
- **Antigravity accounts showed no models.** Three separate faults stacked on the same path, all of which had to go for a catalog to appear:
  - **The live model list was parsed as the wrong shape.** `fetchAvailableModels` answers with `models` as a map keyed by model id (`ModelsEntry` → `ModelDetails`) and names the context window `maxTokens`, but the parser expected an array of `{modelId, inputTokenLimit}`. `json.Unmarshal` failed, the account fell back to the five static models, and the dashboard reported "Model list unavailable". The map shape is now read, with `models/`-prefixed keys normalised and a stable ordering so a refresh does not reshuffle the picker.
  - **The request sent a field the API does not have.** `FetchAvailableModelsRequest` carries `project`, `request_id`, `entitlement` and `location` — there is no `metadata`, and sending one was answered with `400 Invalid JSON payload received. Unknown name "metadata"`.
  - **A token rotation invalidated the account's own model discovery.** `catalogIdentities` is built from the account record at `Reload()` and re-checked in `SetModelListForAccount` to reject discovery that finished against a superseded connection — but `UpdateToken` wrote the rotated credential into `p.accounts` and left `catalogIdentities` holding the old one, so every discovery completed after a routine refresh failed the comparison and was discarded as "account changed during model discovery". The account then stayed at "0 cached models" until the next restart. A rotation now moves the stored identity with it; a genuine credential swap is still refused.
- **Antigravity project discovery failed on macOS.** `metadata.platform` was sent as `MACOS`, which is not a member of the `ClientMetadata.Platform` enum the API validates against, so `loadCodeAssist` answered `400 INVALID_ARGUMENT` and the account finished setup without a `cloudaicompanionProject` — every later request then re-ran discovery and failed the same way. The enum is per-OS per-arch (`DARWIN_AMD64`, `DARWIN_ARM64`, `LINUX_AMD64`, `LINUX_ARM64`, `WINDOWS_AMD64`), not the bare OS family, so the mapping now carries the architecture suffix; Windows reports `AMD64` because the enum has no ARM64 member. The `Client-Metadata` header shares the value, since both are the same proto server-side.
- **SOTA aliases no longer inherit fabricated Claude 5 metadata.** `model-S`/`model-T`/`model-O`/`model-A` were treated as 1M/128K Claude 5 models, and Claude Code picker rows were given `behavesAs` profiles they never advertised. Catalog metadata from the gateway now wins; missing metadata stays unset.
- **Concurrent map read/write crash.** `SetBoolSetting` / `SetStringSetting` released `cfgLock` before calling `Save()`, so a concurrent setting write could race the marshal and kill the process with an unrecoverable runtime throw.
- **Account pool handed out pointers into its own slice.** Every selector now returns a copy; callers writing `AccessToken` / `ExpiresAt` through the returned account could previously corrupt a token mid-refresh or lose the update entirely when `Reload()` replaced the slice.
- **A panic in any spawned goroutine took down the whole proxy**, dropping every in-flight stream. `net/http` only recovers its own handler goroutines; all 14 self-spawned goroutines now run under a `safeGo` recover guard that logs the panic and its stack.
- Compression settings are read through an immutable snapshot taken under the lock, so a live settings change can no longer tear a string field mid-request; `InitCompressionConfig` and the admin read path hold the right mutex.
- Capability routing no longer holds the pool write lock across a config read — it took `Lock` for a read-only selection and then acquired `cfgLock`, serialising all capability routing against chat routing.
- The bulk account refresh patches only token and ban fields, instead of replacing the whole record and clobbering usage counters a live request had just bumped.
- Usage flush no longer discards write errors or clears its dirty flag on failure (a full disk silently dropped records permanently), and writes temp+rename so a crash mid-write cannot truncate `usage_daily.json`.
- **Client disconnects now cancel the upstream request.** Every chat path derives from `r.Context()`, so an abandoned stream releases its account immediately instead of holding it — and billing tokens — until the 15-minute idle timeout. The failover loop recognises a cancellation as the client leaving rather than an account fault, so one disconnect no longer walks the pool recording a failure against every account.
- Changing the admin password revokes every outstanding session token; previously a rotation left existing tokens valid for their full 12 hours.
- The usage flush writes to a uniquely-named temp file, so a shutdown flush racing the 30-second ticker can no longer splice two writes into one corrupt file that is then silently discarded on load.
- A compression settings change persists after releasing the settings lock, instead of holding it across six fsynced config writes while every in-flight request waits to read those settings.
- The Codex branch of the bulk refresh patches only the ban fields, matching the Kiro branch; it previously rewrote the whole record and reset usage counters that live requests had bumped during the pass.
- **Usage charts read UTC**, matching the UTC storage keys. In a non-UTC zone the chart's "today" column and `?period=today` disagreed nightly. Separately, the hourly "today" window was filled from *yesterday*: it snapped to midnight and then subtracted 24 hours.
- Clean shutdown stops the background loops and flushes usage, stats and any coalesced config save; the final 30-second window was previously lost.
- sqlite auto-import applies `busy_timeout` via `_pragma` (the `_busy_timeout` DSN form is silently ignored by `modernc.org/sqlite`), limits itself to one connection, and reports a partial table listing as an error instead of "key absent".
- **Chat Completions parameters the IR could not express were dropped on the way to external gateways.** The route goes client JSON → `OpenAIRequest` → Kiro IR → rebuilt upstream body, and the IR was shaped for native Kiro, so every parameter it could not model vanished at the first hop while the request still succeeded with the upstream's defaults. Measured on a 20-key body, 12 were lost (`stop`, `seed`, `response_format`, `parallel_tool_calls`, penalties, `user`, and vendor extensions); a live A/B confirmed the consequence — with `stop: ["\n15"]` the direct call returned 1..14 while the proxied call ran to 30. Rather than declaring those twelve (which reopens the hole the next time OpenAI ships a parameter), `OpenAIRequest.UnmarshalJSON` now captures every undeclared top-level key as verbatim JSON and the external adapter re-attaches it. `stream`/`stream_options`, `n`, and `logprobs` are deliberately blocked: the proxy owns its stream settings, merges every choice into one stream, and reads no logprob field.
- **`reasoning_effort` sent on the chat route was silently dropped, so external gateways always used their default thinking budget.** `OpenAIRequest` had no field for it. It is now a declared, whitelisted field: `normalizeReasoningEffort` drops an unknown level to empty so a gateway that 400s on an unfamiliar vocabulary never receives it, and an effort-only request (no tokens/temperature/top_p) still builds the inference config. This is the same parameter the generic passthrough would otherwise forward unvalidated, so it travels the typed path once — pinned by a merge-invariant test.
- **A stream cut mid-response charged a cooldown to a healthy account.** The OpenAI chat parser reports a truncated stream as `external SSE stream ended before a terminal finish_reason or [DONE]`, a wording no classifier owned (only the Anthropic `message_stop` and blank-output shapes matched), so it fell to `handleAccountFailure`'s default branch. On a single-account pool three strikes parked the account for a minute and every request inside that window aborted with `no account found` — 54 cooldowns and 77 aborts in one live day. It now classifies as upstream truncation (rotate without cooldown) and as transient (retry in place, gated on `responseStarted`).
- **Cloudflare 5xx edge errors were unclassified.** 520/521/522 sit between the Cloudflare edge and the origin, so none can be a credential fault, yet they matched no marker and landed in the default branch charging a cooldown; 524 only ever classified correctly by accident because its error page contains the word "timeout". All of 520–527 are now transient. Deliberately not a blanket "any 5xx": HTTP 500 is how new-api gateways answer a keyword-scanner hit, which `IsContentBlockedError` owns.
- **The per-account refresh button did not refresh plan windows.** `POST /admin/api/accounts/{id}/refresh` (what the dashboard button calls) refreshed the model list and credit balance for an external account but not the subscription windows, so it reported success while the 5-hour bars kept showing the value from the last background cycle. Routed through `refreshAccountFull` so the button, the manual refresh-all, and the periodic cycle all do the same work per account.

### Added
- **Per-account Responses API dialect for external providers.** An `external_openai` account can now send the Responses wire shape instead of chat completions, selectable when the key is added (`externalApiDialect`, plus an optional `responsesPath` for gateways that serve Responses behind a prefix). This is required by gateways whose backend speaks only Responses — a reseller of ChatGPT Codex subscription capacity, for example — where a chat-completions request forces a lossy internal translation. The wire translation is shared with the Codex adapter and now lives in `responses_upstream.go`; Codex behaviour is pinned byte-identical by a golden test. Chat completions remains the default, because most resale gateways serve chat only.
- GitHub Actions CI runs `go build`, `go vet` and `go test -race` on every push to `main` and every PR — previously nothing verified Go code.
- Tests: `auth` 15.0% → 50.2%, `pool` 59.9% → 88.2% coverage, covering OAuth refresh/exchange/decode for every provider, the model-aware pool selector, error recording and cooldowns, and the CLI-config writers.
- **Plan-window quota for new-api gateways.** An `external_openai` account backed by a new-api gateway (VSLLM among them) sells rolling plan windows — a 5-hour and a 7-day subscription running in parallel — and the operator had no way to see how full the current window was before a turn started failing. The gateway's admin API (`GET /api/subscription/self`, authenticated with the console System Access Token plus a matching `New-Api-User` id, neither of which the inference `sk-` key can supply) reports `used_percent` and the reset timestamps per subscription. The proxy polls it on the existing 10-minute external pass, caches one row per active subscription on the account, and renders each as a quota bar sorted shortest-window-first so the nearest binding constraint is on top. The window length is derived from `next_reset_time - last_reset_time` rather than assumed (the same account runs 18000s and 604800s windows at once), expired rows are dropped, and a `success:false` answer — how this fork signals both an auth mismatch and an admin-only route — is treated as an error so the last good snapshot is kept rather than blanked. The System Access Token is never serialized back to the browser: the API reports `extAdminConfigured` and the uid only.

### Changed
- Docker: pinned `alpine:3.21` runtime, non-root `65532`, healthcheck via the bundled busybox `wget`; `docker-compose.yml` drops the obsolete `version:` key.
- `web/escape.js` holds the single `escapeHtml` / `escapeAttr` implementation, replacing two divergent copies; the unreferenced 2 MB `web/icon.svg` is deleted.

## [0.2.0] — 2026-07-18

### Added
- **Instructions-based cache key** — `payloadCacheKey` now derives the cache key from `hash(instructions)` (the system prompt) instead of `hash(conversationID)`. All conversations sharing the same system prompt share one cache entry, even across different conversations and agents.
- **Async cache warming** — newly rotated accounts receive a background warmup request so the first real request is already a cache hit. Warming runs in a goroutine and never blocks the request path.
- **Warming dedup** — a `cacheWarming` flag map prevents concurrent requests to the same account + cache key from triggering duplicate warmups.
- **Token threshold** — prompts under 1024 tokens skip warming to avoid wasting quota on short prompts that won't benefit from caching.
- **Cache-sticky pinning** — `GetNextForModelWithCacheKey` pins consecutive turns from the same conversation to the same upstream account so the provider's prompt cache stays hot. TTL: 30 minutes.
- **Codex usage tracking** — `CodexPrimaryUsedPercent`, `CodexSecondaryUsedPercent`, `CodexPrimaryResetAt`, `CodexSecondaryResetAt` fields on accounts, populated from `x-codex-*` response headers.
- **External OpenAI-compatible provider support** — `AuthMethod: "external_openai"` with credit balance tracking via `/api/me`.
- **Combo fallback chains** — per-combo strategy override (`fallback` or `round-robin`) with sticky round-robin limit.
- **Provider-aware routing** — Claude models prefer external OpenAI-compatible accounts; GPT models prefer Codex accounts.
- **Per-model cooldown** — quota/auth failures lock only the affected model, not the whole account.
- **Web admin panel** — manage accounts, settings, combos, API keys, usage, cache stats, compression, pool strategy. i18n: EN / CN / VN.
- **Per-account outbound proxy** — global or account-level SOCKS5 / HTTP proxy.
- **Prompt filter system** — custom regex rules via admin panel; built-in Claude Code CLI system prompt replacement.
- **Thinking mode** — configurable suffix trigger, output format (`reasoning_content` / `thinking` / `think`).
- **12 auth methods** — AWS Builder ID, IAM Identity Center, SSO Token, Social Login, Kiro CLI import, Kiro SSO 3-step browser login, AWS SSO Cache, Kiro Local Cache, Credentials JSON, Kiro Web Cookie, API Key (ksk_), Refresh Token.

### Changed
- **Renamed SuperKiro → OmniProxy** — module name, binary name, Docker image, all user-facing strings. The `superkiro` provider key in config files is kept for backward compatibility.
- **Go version** — bumped to 1.25+.
- **Docker build** — multi-arch (amd64 + arm64) via `docker/build-push-action`.

### Fixed
- SSE error events are now sent instead of JSON when streaming, preventing silent hangs on upstream errors.
- Auto-ban disabled; external accounts are skipped in ModelsCache; ban status is cleared on re-enable.
- Codex accounts no longer hit Kiro DNS errors on refresh.
- `temperature` / `top_p` stripped when forwarding to ChatGPT backend (it rejects these fields).
